Capabilities

Infrastructure is the product.

The interesting work is usually the part users never see: clean boundaries, predictable operations and a short list of moving parts.

Networking & DNS

Segmented container networks, local-only binds and deliberate ingress rules. DNS changes are treated as production changes.

Cloud & edge

Static hosting, custom domains and certificates. The public surface is kept small, documented and easy to reproduce.

Automation

Event-driven workflows that remove repetitive work, with explicit failure paths, timeouts and rollback notes.

Applied AI

Practical assistants and email triage with scoped data access. External providers are named in the relevant privacy policy.

Security & privacy

Least privilege, isolated services and no unnecessary public surface. Secrets stay out of the repository.

Documentation

Runbooks, publication checklists and rollback notes. If a change cannot be reversed, it is not ready.

Approach

Boring where it matters.

The goal is not to run the most services. It is to run a small number of things well, know exactly what they touch, and be able to undo a change without drama.

  1. 01

    Expose as little as possible

    Public pages are static. Applications are not offered as public endpoints from this site, and access details are kept private.

  2. 02

    Isolate by default

    Each workload gets its own container network, data volume and credentials. A problem in one service should not become a problem in another.

  3. 03

    Make it reversible

    Changes are documented with a rollback path before they are promoted. Backups and restore steps are part of the change, not an afterthought.

  4. 04

    Disclose the data path

    If a service uses Google data or an external AI provider, the policy names it, explains why, and states what is stored and for how long.

  5. 05

    Keep the public face honest

    No certifications, partnerships or Google approvals are implied unless they actually exist. Where something is pending confirmation, it is flagged before publication.

Google API disclosure

Google access, in plain English.

Marvin and Inbox Zero each use a limited set of Google APIs. Their privacy policies describe what is accessed, why, where it is stored and which processors are involved. Both include the Google API Services User Data Policy Limited Use statement.

These are private deployments. Nothing on this website grants access to a Google Account, and no Google approval or certification is claimed.
