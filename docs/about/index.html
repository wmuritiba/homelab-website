Profile

A personal lab with production discipline.

The homelab is a private environment for running systems that are useful beyond a lab: family automation, email management and internal operations.

I work across the layers that make a service dependable: the operating system, the network boundary, the container runtime, the automation layer and the data path. The interesting part is usually the seam between them.

The approach is deliberately small. Understand what the system touches, limit the public surface, write down the failure and rollback paths, and keep the public description aligned with the private reality. A service is not finished when it starts; it is finished when it can be operated and explained.

This website is a portfolio and a public reference for the projects’ policies. It is not a company, a managed service or a public hosting platform.

Principles

Small, reversible, explainable.

The goal is not to run the most services. It is to run a small number of things well and to know exactly what they touch.

  1. 01

    Keep the public surface small

    Public pages are static. Applications are not offered as public endpoints from this site, and access details are kept private.

  2. 02

    Separate what can be separated

    Dedicated container networks, data volumes and credentials reduce the chance that one service becomes another service’s problem.

  3. 03

    Make changes reversible

    Backups and restore steps belong to the change, not to an afterthought. A change without a rollback path is not ready.

  4. 04

    Keep the public story honest

    No certifications, partnerships or Google approvals are implied unless they exist. Unverified claims are marked as pending, not smoothed over.
